# Nexus Backend Integration Guide

This document outlines the API contracts and data structures required for the Nexus professional profile page. The frontend is fully implemented with mock data and is ready to connect to the backend APIs.

## Frontend Structure

- **Profile Page**: `src/profile/ProfilePage.tsx`
- **Components**: `src/profile/components/`
- **Types**: `src/profile/types/profile.ts`
- **Mock Data Service**: `src/profile/lib/mockData.ts`

## Required API Endpoints

The following functions in `src/profile/lib/mockData.ts` need to be replaced with actual API calls:

### 1. Profile Management

#### GET /api/profile
Get the current user's profile.

**Response (Profile):**
```typescript
{
  id: string;
  userId: string;
  fullName: string;
  email: string;
  avatarUrl?: string;
  title: string;
  company: string;
  location: {
    city: string;
    country: string;
  };
  phone?: string;
  website?: string;
  headline: string;
  bio: string;
  expertise: string[];
  industry: string;
  interests: string[];
  completionPercentage: number;
  createdAt: string;
  updatedAt: string;
}
```

#### PUT /api/profile
Update the user's profile.

**Request:** Partial<Profile>
**Response:** Updated Profile

#### POST /api/profile/avatar
Upload a profile avatar image.

**Request:** FormData with file
**Response:** `{ avatarUrl: string }`

### 2. Networking Intentions

#### GET /api/profile/intentions
Get the user's networking intentions.

**Response (NetworkingIntention[]):**
```typescript
{
  id: string;
  type: 'offer' | 'seek';
  category: string;
  description: string;
  eventId?: string;
  eventName?: string;
}
```

#### PUT /api/profile/intentions
Update networking intentions.

**Request:** NetworkingIntention[]
**Response:** Updated NetworkingIntention[]

---

### 3. Event Participation

#### GET /api/profile/events
Get the user's event participations.

**Response (EventParticipation[]):**
```typescript
{
  id: string;
  eventId: string;
  eventName: string;
  eventDate: string;
  location: string;
  organizer: string;
  status: 'upcoming' | 'past' | 'cancelled';
  role: string;
}
```

---

### 4. Professional Network

#### GET /api/profile/connections
Get the user's professional connections.

**Response (Connection[]):**
```typescript
{
  id: string;
  profileId: string;
  fullName: string;
  title: string;
  company: string;
  avatarUrl?: string;
  status: 'accepted' | 'pending' | 'requested';
  connectedAt?: string;
  upcomingMeeting?: {
    date: string;
    time: string;
  };
}
```

---

### 5. Company Membership

#### GET /api/profile/company
Get the user's company membership.

**Response (CompanyMembership):**
```typescript
{
  id: string;
  companyId: string;
  companyName: string;
  logoUrl?: string;
  industry: string;
  role: string;
  status: 'active' | 'pending' | 'none';
  joinedAt?: string;
}
```

---

### 6. Privacy Settings

#### GET /api/profile/privacy
Get the user's privacy settings.

**Response (PrivacySettings):**
```typescript
{
  profileVisibleInDirectory: boolean;
  publicBusinessCard: boolean;
  shareEmail: boolean;
  sharePhone: boolean;
  appearInSuggestions: boolean;
}
```

#### PUT /api/profile/privacy
Update privacy settings.

**Request:** PrivacySettings
**Response:** Updated PrivacySettings

---

### 7. Digital Business Card

#### GET /api/profile/business-card
Get the business card data based on privacy settings.

**Response (BusinessCard):**
```typescript
{
  fullName: string;
  title: string;
  company: string;
  avatarUrl?: string;
  email?: string; // Only if shareEmail is true
  phone?: string; // Only if sharePhone is true
  website?: string;
  qrCodeUrl?: string; // Generated by backend
}
```

## Database Schema Recommendations

### profiles table
```sql
- id (uuid, primary key)
- user_id (uuid, foreign key to auth.users)
- full_name (text)
- email (text)
- avatar_url (text)
- title (text)
- company (text)
- location_city (text)
- location_country (text)
- phone (text)
- website (text)
- headline (text)
- bio (text)
- expertise (jsonb array)
- industry (text)
- interests (jsonb array)
- completion_percentage (integer)
- created_at (timestamp)
- updated_at (timestamp)
```

### networking_intentions table
```sql
- id (uuid, primary key)
- profile_id (uuid, foreign key to profiles)
- type (enum: 'offer', 'seek')
- category (text)
- description (text)
- event_id (uuid, nullable, foreign key to events)
- created_at (timestamp)
```

### event_participations table
```sql
- id (uuid, primary key)
- profile_id (uuid, foreign key to profiles)
- event_id (uuid, foreign key to events)
- status (enum: 'upcoming', 'past', 'cancelled')
- role (text)
- joined_at (timestamp)
```

### connections table
```sql
- id (uuid, primary key)
- requester_id (uuid, foreign key to profiles)
- receiver_id (uuid, foreign key to profiles)
- status (enum: 'accepted', 'pending', 'requested')
- connected_at (timestamp)
```

### company_memberships table
```sql
- id (uuid, primary key)
- profile_id (uuid, foreign key to profiles)
- company_id (uuid, foreign key to companies)
- role (text)
- status (enum: 'active', 'pending')
- joined_at (timestamp)
```

### privacy_settings table
```sql
- id (uuid, primary key)
- profile_id (uuid, foreign key to profiles, unique)
- profile_visible_in_directory (boolean)
- public_business_card (boolean)
- share_email (boolean)
- share_phone (boolean)
- appear_in_suggestions (boolean)
```

## Authentication Integration

The frontend uses Supabase Auth. The profile page:
- Requires an authenticated session
- Redirects to `/login` if not authenticated
- Uses the session user ID to fetch profile data

The existing Supabase client in `src/auth.js` should be used for all authenticated requests.

## Integration Steps

1. **Replace mock data functions**: Update `src/profile/lib/mockData.ts` to call actual API endpoints
2. **Implement API endpoints**: Create the backend endpoints as specified above
3. **Set up database tables**: Create the recommended schema
4. **Configure RLS policies**: Ensure users can only access their own data
5. **Test integration**: Verify the profile page loads real data

## Notes

- All mock functions include simulated delays to mimic network latency
- The frontend includes loading states and error handling
- Type definitions in `src/profile/types/profile.ts` should match your backend responses
- The profile completion percentage is calculated based on filled fields (frontend can calculate this or backend can provide it)
- Event-specific networking intentions are supported via the `eventId` field
